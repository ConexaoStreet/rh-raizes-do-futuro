# RH UI Redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

**Goal:** Redesenhar o RH como um produto de gestão de pessoas sofisticado, humano e editorial sem alterar regras de negócio, permissões, Supabase ou contratos de API.

**Architecture:** A implementação será incremental e reversível. O CSS atual permanece como base enquanto uma camada nova de redesign é aplicada por arquivo dedicado; componentes-base recebem variações compatíveis e o shell é reorganizado sem alterar rotas. Mudanças de página entram por módulos, cada uma com testes e E2E próprios.

**Tech Stack:** React 19, TypeScript 5.9, React Router 7, Supabase JS 2.116, Lucide React, Recharts, Radix Dialog, Vitest, Playwright, Vite/Vercel.

**Spec:** docs/specs/2026-09-27-ui-redesign-rh-ti.txt

## Global Constraints

- RH e Central T.I. não devem parecer o mesmo produto.
- Não alterar regras de negócio, Supabase, Auth, RLS, permissões ou contratos de API sem necessidade explícita.
- Não remover módulos existentes.
- Não recriar banco, autenticação ou infraestrutura.
- Não publicar segredos.
- Preservar backup/pre-ui-redesign-2026-09-27.
- Mobile pequeno 320–479px; mobile 480–767px; tablet 768–1099px; desktop 1100–1599px; desktop largo 1600px+.
- Inputs mobile >= 16px, safe-area iOS, touch targets >= 44px.
- Motion padrão 140–220ms e respeito a prefers-reduced-motion.
- Contraste WCAG AA em texto funcional.
- Toda etapa entra por branch/PR com lint, unit, database, build, bundle e E2E.
- Webflow e Canva serão usados como laboratório visual/referência antes da implementação; não entram como dependência de runtime.
- Figma pode complementar o trabalho quando a cota MCP voltar, sem bloquear a execução.

## Review Focus

- Viewports extremos/zoom reduzido não podem voltar a produzir layout microscópico ou overflow.
- Perfis sem dashboard.view devem continuar vendo Meu perfil e não receber navegação indevida.
- Cadastro/ativação em etapas deve preservar exatamente os campos e validações existentes.
- Tabelas/listas grandes devem continuar utilizáveis em mobile sem ocultar ações essenciais.
- Tema claro/escuro deve manter contraste e persistência existentes.
