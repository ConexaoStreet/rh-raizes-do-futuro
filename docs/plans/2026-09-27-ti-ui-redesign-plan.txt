# Central T.I. UI Redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

**Goal:** Redesenhar a Central T.I. como um console técnico interno mais preciso, denso e operacional sem alterar contratos de Supabase, funções administrativas ou regras de segurança.

**Architecture:** O redesign mantém a aplicação React/Vite atual e introduz uma camada visual específica da T.I., separada do RH. O App.tsx monolítico será dividido apenas onde isso melhora limites claros de UI, preservando estados, chamadas e permissões. Cada extração mantém as interfaces atuais e é verificada antes de avançar.

**Tech Stack:** React 19, TypeScript 5.9, Supabase JS, Lucide React, Vite/Vercel, Vitest/Playwright.

**Spec:** docs/specs/2026-09-27-ui-redesign-rh-ti.txt

## Global Constraints

- A T.I. deve permanecer visualmente distinta do RH.
- Não alterar Supabase, Auth, RLS, permissões, Edge Functions ou contratos de API sem necessidade explícita.
- Não remover módulos.
- Não migrar para Webflow/Wix/Base44.
- Preservar e-mail/senha e código semanal no login.
- Mobile pequeno 320–479px; mobile 480–767px; tablet 768–1099px; desktop 1100–1599px; desktop largo 1600px+.
- Inputs mobile >=16px; safe-area iOS; touch targets >=44px.
- Motion 140–220ms e prefers-reduced-motion.
- Estados critical/warn/ok não dependem somente de cor.
- Toda etapa passa CI/build/bundle/E2E antes de merge.

## Review Focus

- Estados partial/error/needs_secret/needs_connection precisam continuar distinguíveis e legíveis.
- Ações destrutivas de usuários/storage/configuração não podem perder confirmação/contexto.
- Payload/request técnico do Datasul deve continuar legível sem quebrar em mobile.
- Overview não pode mascarar módulos que falharam durante reload parcial.
- Login por código semanal e e-mail/senha devem continuar semanticamente separados e funcionais.
